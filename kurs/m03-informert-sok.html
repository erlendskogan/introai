Informert søk: Greedy, A* og heuristikker

Uinformert søk leter i blinde. Med en god «magefølelse» for hvor målet ligger – en heuristikk – kan søket gå rett mot målet. Denne modulen gjør deg i stand til å kjøre A* for hånd slik sensor vil ha det, avgjøre om en heuristikk er admissibel og konsistent, og forklare hvorfor A* finner den billigste løsningen.

Læringsmål
  • Forklare hva en heuristisk funksjon h(n) og en evalueringsfunksjon f(n) er, og hvordan DFS, UCS, greedy best-first og A* bare er Best-First-Search med ulik f.
  • Kjøre greedy best-first search og A* for hånd på en graf, med frontier-tabell (g, h, f), alfabetisk tiebreaking og sen måltest – og skrive svaret i eksamensformat.
  • Definere og sjekke admissibilitet (h ≤ h*) og konsistens (h(n) ≤ c(n,n′) + h(n′)) på en gitt graf, og forklare sammenhengen mellom dem.
  • Forklare beviset for at A* er optimal, hva konturer er, og hvilke noder A* garantert ekspanderer.
  • Forklare forskjellen på tree-like search, graph search med gjenåpning og graph search med closed-liste – og hvorfor sistnevnte trenger konsistens.
  • Kjenne weighted A*, IDA*, RBFS, SMA* og beam search på overordnet nivå.
  • Lage heuristikker med relaxed problems, regne h1/h2 for 8-puslespillet, avgjøre dominans og regne effektiv forgreningsfaktor.
Hvorfor dette er viktig til eksamen

Informert søk er det temaet som har dukket opp på absolutt hver eneste eksamen 2015–2025, og ofte med høy vekt:

Det gir typisk 10–20 % av totalpoengene. Poengene ligger i å vise hvert steg (frontier med g+h=f), ikke bare svaret.

1. Fra blindt til informert søk

Intuisjon

Tenk deg at du står i Arad i Romania og skal til Bucharest, uten kart, men med et kompass og et skilt som sier «Bucharest: 366 miles i luftlinje». En blind agent (BFS, UCS) prøver alle veier like mye – også de som peker bort fra målet. En informert agent bruker skiltet: veier som fører nærmere Bucharest prøves først. Skiltet er ikke perfekt (veier svinger), men det er et godt hint.

I modul 2 så du at alle søkealgoritmene våre har samme skjelett: vi har en grense (frontier)Mengden noder vi har generert (oppdaget), men ennå ikke ekspandert. Kalles også «open list». av noder som venter, og i hvert steg velger vi én node å ekspandere (generere barna til). Det eneste som skiller algoritmene, er hvilken node vi velger. Et informert søkSøk som bruker domenespesifikk kunnskap om hvor målet ligger, i form av en heuristisk funksjon h(n), for å velge hvilken node som skal ekspanderes. bruker et estimat av hvor langt det er igjen til målet når det velger.

Heuristisk funksjon h(n)

En heuristisk funksjonh(n) = estimert kostnad for billigste vei fra tilstanden i node n til en måltilstand. Avhenger bare av tilstanden, ikke av hvordan vi kom dit. er en funksjon h : tilstander → ℝ slik at

h(n) = estimert kostnad for den billigste veien fra tilstanden i n til en måltilstand

Tre ting å merke seg:

  • h ser bare framover. Den ser kun på tilstanden i n, ikke på veien dit. To noder med samme tilstand har samme h.
  • h(mål) = 0 i alle fornuftige heuristikker (det er ingenting igjen å gå).
  • h er domenekunnskap. Den kan ikke regnes ut fra ACTIONS og RESULT alene – noen må ha lagt inn kunnskap om problemet. For Romania er det luftlinjeavstandenhSLD(n): avstanden i rett linje fra byen n til Bucharest. Klassisk heuristikk for ruteplanlegging. hSLD til Bucharest.

Algoritme: Best-First-Search (R&N fig. 3.7) 
function BEST-FIRST-SEARCH(problem, f) returns a solution node or failure
 1  node ← NODE(STATE = problem.INITIAL)
 2  frontier ← a priority queue ordered by f, with node as an element
 3  reached ← a lookup table, with one entry with key problem.INITIAL and value node
 4  while not IS-EMPTY(frontier) do
 5     node ← POP(frontier)                         // lavest f (likhet: alfabetisk)
 6     if problem.IS-GOAL(node.STATE) then return node   // SEN måltest
 7     for each child in EXPAND(problem, node) do
 8        s ← child.STATE
 9        if s is not in reached or child.PATH-COST < reached[s].PATH-COST then
10           reached[s] ← child
11           add child to frontier
12  return failure

Linje for linje:

  • 1–3: Start med startnoden i grensen og i tabellen reached (alle tilstander vi har sett, med beste kjente vei).
  • 5: Ta ut noden med lavest f. På eksamen brytes likhet (tie) nesten alltid alfabetisk.
  • 6: Måltesten skjer når noden tas ut av grensen (sen måltest / «late goal test»), ikke når den genereres. Dette er avgjørende for at A* skal være optimal – en dårlig vei til målet kan ligge i grensen en stund uten å bli valgt.
  • 7–11: Generer barna. Et barn legges bare inn hvis tilstanden er ny, eller vi har funnet en billigere vei dit enn før. Dette er det som gjør algoritmen til graph search (den husker hvor den har vært), og det er linje 9 som lar A* «ombestemme seg» – mer om det i seksjon 7.

Vanlig feil (fra foilene: «common gotchas»)

g(n) er summen av hele veien fra start til n, mens h(n) er bare tallet som står ved n. Studenter legger ofte sammen h-verdiene langs veien, eller glemmer å summere g. Eksempel: Veien S→A→C med kostnader 4 og 4 gir g(C) = 8, og f(C) = 8 + h(C) – ikke 4 + h(C), og ikke 8 + h(A) + h(C).

Hvilken evalueringsfunksjon gjør Best-First-Search til uniform-cost search?

  • f(n) = h(n)
  • f(n) = g(n) + h(n)
  • f(n) = g(n)
  • f(n) = −depth(n)
UCS velger billigste vei hittil, altså f = g. Merk også: A* med h(n) = 0 for alle n er nøyaktig UCS (eksamen 2017 4d: «Uniform cost search is a special case of A*» – True).

Veien S → A → C har kantkostnader 4 og 4. h(S) = 5, h(A) = 3, h(C) = 7. Hva er f(C) for A*?

g(C) = 4 + 4 = 8 (hele veien), h(C) = 7 (bare ved C). f(C) = 8 + 7 = 15. h(S) og h(A) har ingenting å si for f(C).

2. Greedy best-first search

Greedy best-first searchBest-first search med f(n) = h(n): ekspanderer alltid den noden som ser ut til å være nærmest målet, uten å bry seg om hva det har kostet å komme dit. bruker f(n) = h(n). Den er «grådig» fordi den i hvert steg prøver å komme så nær målet som mulig, uten å se på hva veien har kostet så langt.

Intuisjon

Greedy er som å kjøre bil ved å alltid velge avkjøringen som peker mest mot målet. Ofte kommer du fram fort – men du kan havne på en lang omvei, i en blindvei, eller kjøre i ring.

Eksempel: Arad → Bucharest

Start: frontier = {Arad:366}. Arad er ikke mål. Vi ekspanderer Arad og får Sibiu (h = 253), Timisoara (329) og Zerind (374).

frontier = {Sibiu:253, Timisoara:329, Zerind:374}. Sibiu har lavest h → ekspander Sibiu. Barn: Arad (366), Fagaras (176), Oradea (380), Rimnicu Vilcea (193).

frontier = {Fagaras:176, R.Vilcea:193, Timisoara:329, Zerind:374, Oradea:380} (i tree-like søk ville også Arad:366 ligget der igjen). Fagaras har lavest h → ekspander. Barn: Sibiu (253) og Bucharest (0).

Bucharest (h = 0) tas ut og er målet. Løsning: Arad → Sibiu → Fagaras → Bucharest, kostnad 140 + 99 + 211 = 450. Greedy ekspanderte bare noder på løsningsveien – veldig effektivt – men løsningen er ikke optimal: veien via Rimnicu Vilcea og Pitesti koster 418.

Eksempel: greedy i en løkke

Grafen under er fra forelesningen (og eksamen 2023, oppg. 2.1). Kantene er rettet, og A har en løkke tilbake til seg selv med kostnad 13. h(A) = h(B) = h(C) = 3, h(G) = 0.

  • Ekspander S: A og B har begge h = 3 → alfabetisk vinner A.
  • Ekspander A: genererer A igjen (via løkken, h = 3) og C (h = 3). Frontier = {A:3, B:3, C:3} → alfabetisk vinner A igjen.
  • Ekspander A: nøyaktig det samme skjer. Med tree-like search gjentar dette seg i det uendelige: S, A, A, A, … – ingen løsning.
  • Med graph search (husker reached) blir A-kopien via løkken forkastet (g = 17 er ikke bedre enn 4). Da: S, A, B, (G) med veien S→B→G, kostnad 17 – mens den optimale er S→A→C→G med kostnad 12.

Vis et forslag

Fordi effektivitet og optimalitet er to ulike ting. Greedy er rask fordi den ignorerer kostnaden bak seg, men det er nettopp derfor den kan velge en dyr vei (Fagaras-veien har en lang kant på 211). Hvis vi trenger den billigste veien (ruteplanlegging, logistikk), må vi også ta hensyn til g. Hvis vi bare trenger en løsning raskt, kan greedy (eller weighted A*) være et godt valg.

3. A*-søk: f(n) = g(n) + h(n)

A*-søkBest-first search med f(n) = g(n) + h(n): estimert kostnad for den billigste løsningen som går gjennom n. Uttales «A-stjerne» / «A-star». kombinerer det beste fra UCS (g, det vi vet) og greedy (h, det vi gjetter):

f(n) = g(n) + h(n) = (kostnad hit) + (estimert kostnad herfra til mål)

f(n) er altså et estimat av totalkostnaden for den beste løsningen som går gjennom n. A* ekspanderer alltid noden med lavest slikt estimat.

Intuisjon

UCS sier «jeg har gått minst», greedy sier «jeg er nærmest». A* sier «hele turen min, inkludert det jeg allerede har gått, ser kortest ut». En node langt fra start men nær mål kan tape mot en node som er litt lenger fra mål men mye billigere å ha nådd.

Eksempel: Arad → Bucharest med A*

Start i Arad: g = 0, h = 366, f = 366. Ekspander Arad: Sibiu f = 140 + 253 = 393, Timisoara f = 118 + 329 = 447, Zerind f = 75 + 374 = 449.

frontier = {Sibiu:393, Timisoara:447, Zerind:449}. Ekspander Sibiu: Fagaras 239 + 176 = 415, Oradea 291 + 380 = 671, R. Vilcea 220 + 193 = 413. (Arad via Sibiu: 280 + 366 = 646 – i graph search forkastes den fordi Arad allerede er nådd billigere.)

frontier = {R.Vilcea:413, Fagaras:415, Timisoara:447, Zerind:449, Oradea:671}. Ekspander Rimnicu Vilcea: Craiova 366 + 160 = 526, Pitesti 317 + 100 = 417.

frontier = {Fagaras:415, Pitesti:417, Timisoara:447, Zerind:449, Craiova:526, Oradea:671}. Ekspander Fagaras: Bucharest genereres med f = 450 + 0 = 450. Men Bucharest er ikke billigst i grensen – Pitesti (417) er det. Vi stopper ikke!

frontier = {Pitesti:417, Timisoara:447, Zerind:449, Bucharest:450, Craiova:526, Oradea:671}. Ekspander Pitesti: ny vei til Bucharest med g = 317 + 101 = 418, f = 418 < 450. Den billigere veien erstatter den gamle i grensen.

Bucharest (418) er nå lavest og tas ut → mål! Løsning: Arad → Sibiu → Rimnicu Vilcea → Pitesti → Bucharest, kostnad 418 – den optimale. Ekspansjonsrekkefølge: A, S, R, F, P, (B). Legg merke til at Timisoara og Zerind aldri ble ekspandert.

Nøkkelpoeng: sen måltest

Bucharest lå i grensen med f = 450 i ett helt steg uten å bli valgt. Hadde vi testet for mål da noden ble generert (slik BFS gjør), ville vi returnert 450-veien. A* tester først når noden tas ut av grensen – da vet vi at ingen annen node i grensen har lavere f.

Vanlige feil i A*-oppgaver
  • Stoppe når målet genereres i stedet for når det tas ut (det er BFS som har tidlig måltest).
  • Glemme å oppdatere en node i grensen når en billigere vei dukker opp (Bucharest 450 → 418).
  • Feil tiebreaking: «alfabetisk» gjelder ved lik f. Ved lik f mellom «127» og «127A» kommer «127» først (kortere streng er alfabetisk først) – se 2016-oppgaven.
  • Glemme at grafen er urettet: i en urettet graf er forelderen også et barn. I graph search forkastes den (allerede nådd billigere), i tree-like search legges den inn igjen.
  • Regne f med h langs hele veien i stedet for bare h ved noden.

5. Admissibilitet og hvorfor A* er optimal

A* er bare så god som heuristikken sin. Den viktigste egenskapen er:

Definisjon: admissibel heuristikk

En heuristikk h er admissibelh overestimerer aldri: h(n) ≤ h*(n) for alle n, der h*(n) er den sanne kostnaden for billigste vei fra n til et mål. En admissibel heuristikk er optimistisk. hvis den aldri overestimerer kostnaden til målet:

h(n) ≤ h*(n) for alle noder n

der h*(n)Den sanne (optimale) kostnaden fra n til nærmeste mål. Finnes ved å regne billigste vei baklengs fra målet. er den faktiske kostnaden for den billigste veien fra n til et mål. En admissibel heuristikk er optimistisk.

  • Luftlinje er admissibel: ingen vei kan være kortere enn en rett linje.
  • h(n) = 0 er admissibel (men gir ingen informasjon – A* blir UCS).
  • h(mål) må være 0 for at h skal være admissibel (h*(mål) = 0).
  • Admissibilitet er en egenskap ved hver node: det holder med én node der h(n) > h*(n) for at h ikke er admissibel.

Bevis: admissibel h ⇒ A* er kostnadsoptimal

Intuisjon

Når h er optimistisk, er f(n) en nedre grense for hva en løsning gjennom n kan koste. Så lenge det ligger en node på den optimale veien i grensen, har den f ≤ C*. En dårligere målnode har f = C > C*, så den kommer alltid bak i køen – den optimale veien «vinner» alltid køen.

Boka gir et motsigelsesbevis. Anta at den optimale løsningen koster C*, men A* returnerer en vei med kostnad C > C*. Da må det finnes en node n på den optimale veien som ennå ikke er ekspandert (ellers ville vi ha returnert den optimale). La g*(n) være optimal kostnad fra start til n og h*(n) optimal kostnad fra n til mål. Da gjelder:

f(n) > C* (ellers ville n ha blitt ekspandert før målet med kostnad C) f(n) = g(n) + h(n) (definisjon) f(n) = g*(n) + h(n) (n ligger på en optimal vei, så g(n) = g*(n)) f(n) ≤ g*(n) + h*(n) (admissibilitet: h(n) ≤ h*(n)) f(n) ≤ C* (definisjon: C* = g*(n) + h*(n))

Første og siste linje motsier hverandre. Altså kan A* ikke returnere en suboptimal vei. ∎

Hva skjer når h overestimerer?

Forelesningens eksempel («Essence of the proof»): A–B–C–G med kostnad 1 på hver kant, og en direkte kant A–C med kostnad 999. h(A) = 3, h(B) = 1000, h(C) = 1, h(G) = 0.

A* fra A: B får f = 1 + 1000 = 1001, C får f = 999 + 1 = 1000. C tas ut først, deretter G med f = 1000. A* returnerer A→C→G med kostnad 1000, mens A→B→C→G koster 3. Den overestimerte h(B) fikk den optimale veien til å se dyr ut, så den ble aldri utforsket.

Negative heuristikker (fra forelesningen)

  1. Blir A* optimal hvis h kan være negativ? Negative h-verdier er formelt «optimistiske», men hvis vi tillater h(mål) ≠ 0 (f.eks. h(g) = −999) mister vi garantien – en målnode kan se kunstig billig ut.
  2. Hva betyr en negativ heuristikk? Egentlig ingenting meningsfullt: h skal estimere gjenværende kostnad, og den er aldri negativ når kantkostnadene er positive.
  3. Er det lurt? Nei. Å trekke en stor konstant fra alle h endrer ikke rekkefølgen, og h = 0 (UCS) er i snitt mer informativt enn tilfeldige negative verdier.
Fra boka: når en inadmissibel h likevel gir optimal løsning

(1) Hvis det finnes én optimal vei der h er admissibel for alle nodene på veien, finnes den uansett hva h sier om andre noder. (2) Hvis optimal kostnad er C* og nest beste er C2, og h aldri overestimerer med mer enn C2 − C*, er A* fortsatt optimal.

6. Konsistens (monotonisitet)

Definisjon: konsistent heuristikk

h er konsistentFor hver node n og hvert barn n′ (via handling a): h(n) ≤ c(n, a, n′) + h(n′). Estimatet kan ikke falle mer enn det koster å ta steget. hvis det for hver node n og hvert barn n′ generert av en handling a gjelder:

h(n) ≤ c(n, a, n′) + h(n′)

Ekvivalent: h(n) − h(n′) ≤ c(n, a, n′) – h kan ikke synke mer langs en kant enn kanten koster. Konsistens kalles også monotonisitetSynonym for konsistens. Navnet kommer av at f = g + h da aldri synker langs en vei (er monotont ikke-avtagende)..

Dette er en form for trekantulikhetenI en trekant er én side aldri lengre enn summen av de to andre. For heuristikker: h(n) ≤ c(n,n′) + h(n′).: å «gå direkte» fra n til målet (estimatet h(n)) skal ikke være dyrere enn å først gå til naboen n′ og så ta estimatet derfra. Luftlinjeavstand er konsistent: i Romania er luftlinjen fra Arad aldri lengre enn veien til Sibiu pluss luftlinjen fra Sibiu.

Slik sjekker du konsistens på en graf

  1. List opp alle kanter. Er grafen urettet, må hver kant sjekkes i begge retninger – det blir det samme som |h(n) − h(n′)| ≤ c(n, n′).
  2. For hver retning n → n′: sjekk h(n) ≤ c + h(n′).
  3. Én eneste kant som bryter betingelsen, gjør h inkonsistent. Ta med kanter inn til målet G (h(G) = 0) – eksamen 2017 presiserer at «all pairs, including G» må sjekkes.

Teorem 1: konsistent ⇒ admissibel (men ikke omvendt)

Bevis (induksjon langs den optimale veien). La n = n0, n1, …, nk = G være en billigste vei fra n til målet, og anta h(G) = 0. Ved å bruke konsistens gang på gang:

h(n₀) ≤ c(n₀,n₁) + h(n₁) ≤ c(n₀,n₁) + c(n₁,n₂) + h(n₂) ≤ … ≤ Σ c(nᵢ,nᵢ₊₁) + h(G) = h*(n)

Altså h(n) ≤ h*(n) for alle n. ∎

Omvendt gjelder ikke. Moteksempel fra eksamen 2019: h(B) = 6, h(C) = 2, c(B, C) = 2. h*(B) = 6 (B→C→G = 2 + 4), så h(B) er admissibel, men h(B) = 6 > c(B,C) + h(C) = 4 – inkonsistent.

Teorem 2: konsistent ⇒ f er ikke-avtagende langs enhver vei

Hvis n′ er et barn av n, er g(n′) = g(n) + c(n, a, n′), og derfor

f(n′) = g(n) + c(n, a, n′) + h(n′) ≥ g(n) + h(n) = f(n)

der ulikheten er nøyaktig konsistensbetingelsen. Faktisk er det «hvis og bare hvis»: f er monoton langs alle veier ⇔ h er konsistent.

Konsekvens: Med konsistent h tar A* ut noder i ikke-avtagende f-rekkefølge, og første gang en tilstand tas ut av grensen, er det via en optimal vei. Vi trenger derfor aldri å gjenåpne en ekspandert tilstand – det er dette som gjør closed-liste-varianten av A* trygg (seksjon 7).

Vanlig feil
  • Sjekke bare kanter langs løsningsveien, eller bare noen få kanter. Alle kanter må sjekkes (eksamen 2017 trakk poeng for delvis sjekk).
  • Sjekke bare én retning i en urettet graf.
  • Blande sammen begrepene: admissibel handler om h mot h* (node for node), konsistent handler om h mot naboens h + kantkostnad (kant for kant).
  • Tro at «admissibel ⇒ konsistent». Det er motsatt.

Er heuristikken admissibel og konsistent? Endre h-verdiene i tabellen. Noder som bryter admissibilitet (h > h*) blir røde, og kanter som bryter konsistens blir røde og stiplede. h* regnes ut automatisk (billigste vei baklengs fra målet).

Eksamen 2017 (T/F): «If h is a consistent heuristic, then h is also an admissible heuristic.»

  • False
  • True
True. Bevis ved induksjon langs den optimale veien (forutsatt h(mål) = 0). Omvendt holder ikke: admissibel ⇏ konsistent.

I en urettet graf er c(X, Y) = 3 og h(Y) = 7. Hva er den minste verdien h(X) kan ha uten at kanten X–Y bryter konsistens?

Begge retninger: h(X) ≤ 3 + 7 = 10 og h(Y) ≤ 3 + h(X) ⇒ h(X) ≥ 4. Altså 4 ≤ h(X) ≤ 10, minste verdi 4.

Eksamen 2022 spurte: «Why is consistency a desired property of a heuristic?» Skriv et svar på 2–4 setninger før du ser på forslaget.

Vis et forslag

Med konsistent h er f = g + h ikke-avtagende langs enhver vei. Da tar A* ut tilstander i f-rekkefølge, og første gang en tilstand ekspanderes er det via en optimal vei. Vi slipper altså å gjenåpne noder eller oppdatere allerede ekspanderte noder, noe som sparer tid og minne og gjør implementasjonen enklere (closed-liste). I tillegg er konsistent h automatisk admissibel, så A* blir kostnadsoptimal – og A* med konsistent h er optimalt effektiv. (Den offisielle løsningen nevner trekantulikheten og at konsistens gir admissibilitet og dermed optimalitet.)

8. Konturer, «surely expanded» noder og optimal effektivitet

En nyttig måte å se for seg søket på er konturer«Høydekurver» i tilstandsrommet: kontur c omslutter alle noder med f(n) ≤ c. A* utvider seg i bånd med økende f., som høydekurver på et kart. Innenfor konturen merket 400 ligger alle noder med f = g + h ≤ 400. Fordi A* alltid ekspanderer lavest f, «fyller» den kontur for kontur utover fra start.

La C* være kostnaden til den optimale løsningen. Med konsistent h gjelder:

Hvilke noder ekspanderer A*?
  • A* ekspanderer alle noder som kan nås fra start via en vei der hver node har f(n) < C*. Disse kalles surely expanded nodesNoder som nås via en vei der alle noder har f(n) < C*. A* (med konsistent h) må ekspandere alle disse..
  • A* kan ekspandere noen noder med f(n) = C* (på «målkonturen») før den velger målet – avhenger av tiebreaking.
  • A* ekspanderer ingen noder med f(n) > C*.

Dette gir to viktige begreper:

  • Optimalt effektivA* med konsistent h: enhver annen algoritme som utvider søkeveier fra start og bruker samme heuristikk, må ekspandere minst alle nodene A* garantert ekspanderer (bortsett fra likhet i f = C*).: A* med konsistent h er optimalt effektiv – enhver annen optimal algoritme som utvider veier fra start med samme heuristikk må ekspandere alle surely expanded nodes, for hvilken som helst av dem kunne ha ligget på en enda bedre løsning. (Foilene: «any other search algorithm with the same heuristic values must at least expand all nodes that A* expanded, ignoring ties».)
  • BeskjæringÅ utelukke deler av søketreet uten å undersøke dem. A* beskjærer alle noder med f > C*.: I Romania-eksempelet har Timisoara f = 447 og Zerind f = 449 > C* = 418. 9. Satisficing søk og weighted A*

A* finner det optimale, men kan ekspandere enormt mange noder. Ofte er en løsning som er «god nok» bedre enn en perfekt løsning som kommer for sent. Slike løsninger kalles satisficing«Satisfy + suffice»: en løsning som er god nok, selv om den ikke er optimal. Vi bytter litt kvalitet mot mye raskere søk. (av satisfy + suffice).

Én måte er å bruke en inadmissibel heuristikk som er mer treffsikker. Veiingeniører bruker en omveisindeksDetour index: faktor (typisk 1,2–1,6) som ganges med luftlinjen for å estimere faktisk veilengde. Gir et bedre, men inadmissibelt estimat. (detour index): luftlinje × 1,3 er et bedre estimat av veilengden – men det kan overestimere. Generelt gir dette weighted A*Best-first search med f(n) = g(n) + W·h(n), W > 1. f(n) = g(n) + W · h(n), W > 1
  • Garanti: Hvis optimal kostnad er C*, finner weighted A* (med admissibel h) en løsning med kostnad mellom C* og W · C*. I praksis ofte mye nærmere C*.
  • Boka viser et rutenett der weighted A* med W = 2 utforsker 7 ganger færre tilstander og finner en vei som er bare 5 % dyrere.
  • Foilene kaller det «somewhat-greedy search»: det fokuserer mot målet, men ignorerer ikke kostnaden helt.

10. Minnebegrenset søk: IDA*, RBFS, SMA* og beam search

«The main issue of A* lies on its memory use» (foilene). A* lagrer hele grensen og alle nådde tilstander. Boka beskriver noen triks og noen nye algoritmer. Til eksamen holder det å vite ideen, hva som huskes og egenskapene.

Implementasjonstriks

  • Reference count: fjern en tilstand fra reached når det ikke finnes flere måter å nå den på (f.eks. i et rutenett: etter at den er nådd fra alle fire naboer).
  • Separasjonsegenskapen + forbud mot «U-svinger»: da trenger vi bare sjekke grensen og kan droppe reached.

Beam search

Beam searchBest-first search som bare beholder de k beste nodene (eller de innenfor δ av beste f) i grensen. Sparer minne, men er verken komplett eller optimal. beholder bare de k nodene med best f i grensen og kaster resten (variant: behold alle innenfor δ av beste f). Raskt og minnegjerrig, men ikke komplett og ikke optimal – den optimale veien kan bli kastet.

function RBFS(problem, node, f_limit) returns a solution or failure, and a new f-cost limit
   if problem.IS-GOAL(node.STATE) then return node
   successors ← LIST(EXPAND(node))
   if successors is empty then return failure, ∞

Definisjon: dominans

En admissibel heuristikk h2 dominererh₂ dominerer h₁ hvis h₂(n) ≥ h₁(n) for alle n (begge admissible). Da ekspanderer A* med h₂ aldri flere noder enn med h₁ (bortsett fra uheldig tiebreaking). en annen admissibel heuristikk h1 hvis h2(n) ≥ h1(n) for alle noder n.

  • For 8-puslespillet dominerer h2 h1: en feilplassert brikke har Manhattan-avstand ≥ 1.
  • Hvorfor er det bedre? Alle noder med f(n) < C*, dvs. h(n) < C* − g(n), blir garantert ekspandert. Er h2 ≥ h1, er hver node som er surely expanded med h2 også surely expanded med h1 – men h1 kan i tillegg måtte ekspandere andre. Høyere (men fortsatt admissibel) h = mer informasjon = færre ekspansjoner.

  • Kombiner: h(n) = max{h1(n), …, hk(n)} er admissibel (konsistent hvis alle er det) og dominerer alle komponentene. Ulempen er bare beregningstiden.

Definisjoner du må kunne skrive ned
  • Admissibel: h(n) ≤ h*(n) for alle n (aldri overestimere). Sjekkes node for node mot sann kostnad.
  • Konsistent: h(n) ≤ c(n, a, n′) + h(n′) for alle kanter (trekantulikheten). Sjekkes kant for kant; urettet: |h(n) − h(n′)| ≤ c i begge retninger.
  • Konsistent ⇒ admissibel (ikke omvendt). Konsistent ⇔ f ikke-avtagende langs enhver vei.
  • Dominans: h2 dominerer h1 hvis h2(n) ≥ h1(n) for alle n (begge admissible) ⇒ A* med h2 ekspanderer aldri flere noder. max(h1,…,hk) dominerer alle.
  • Effektiv forgreningsfaktor: N + 1 = 1 + b* + (b*)² + … + (b*)d.
  • Relaxed problem: færre restriksjoner ⇒ optimal kostnad der er admissibel og konsistent. 8-puslespill: fjern «Y tom» ⇒ h2 (Manhattan); fjern også «nabo» ⇒ h1 (feilplasserte).
  • Surely expanded: alle noder med f < C*; kanskje noen med f = C*; ingen med f > C*. A* med konsistent h er optimalt effektiv.
